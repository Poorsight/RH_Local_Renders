## Обнаруженные и исправленные ошибки

### libvips не открывал длинный путь

У секционки RAW существовал и читался Node/Unreal, но POST выдавал `VipsForeignLoad: file ... does not exist`. Полный путь имел 279 символов: имя модели повторялось в имени job и подкаталоге `raw`, а PNG содержал названия материалов. Старые `batch_16_…` имели более короткую верхнюю папку.

Read-only проверка `vipsheader` воспроизвела отказ с обычным путём и успешно прочитала тот же PNG с Windows-префиксом extended-length `\\?\`. Исправление: `processImage` передаёт libvips `path.toNamespacedPath(path.resolve(file))` на Windows. Сами имена, исходные изображения и структура jobs не меняются. Выход libvips пишется в короткую временную папку; перенос на длинный итоговый путь выполняет Node.

После исправления повторный `/api/postprocess` создал все 9 POST секционки за 30,780 с без повторного рендера. `manifest.json`: complete=true, fileCount=9.

### Ошибка POST оставляла общий success

До исправления автоматический POST без очереди выставлял общий `success` даже при `postProcess.state=failed`. Теперь текущий прогон завершается `failed`, RAW сохраняются, сообщение поясняет, что сломалась именно обработка. Отдельный интеграционный тест принудительно ломает запуск POST и проверяет общий failed и сохранность RAW.

Добавлен реальный тест libvips с путями >260 символов и пробелами: длинный и короткий пути дают одинаковые пиксели, источник не меняется. Тесты успешного рендера/возобновления теперь создают настоящие PNG вместо текстовых заглушек, которые раньше скрывались старым ложным success. Таймауты этих тестов учитывают настоящий POST.

Проверено: `npm run build`; **88 тестов, 0 ошибок**. Сбой и повторное выполнение тестов во время разработки исправления не скрыты: до обновления двух старых фикстур они закономерно обнаружили невалидные «PNG»; после исправления фикстур весь набор прошёл.

## Метод попиксельной проверки

`pixels.cjs` читает исходные PNG, сравнивает декодированные 8-битные RGBA. Нет ресайза, автоматического совмещения, изменения экспозиции или подгонки цвета. Если отличается только высота симметричного кропа, изображения дополняются прозрачными строками до базового кадра в памяти; смещения записаны в JSON. PNG при этом не переписываются.

- Exact pixels — совпадение всех четырёх каналов. Прозрачный фон может завышать процент, поэтому он не используется как единственная оценка.
- Silhouette IoU — пересечение/объединение пикселей с alpha >5.
- Visible MAE/RMSE — разница композиции на белом фоне в объединении видимых областей, единицы 0…255. Это сравнение кодовых значений, не DeltaE.
- Native audit — для каждого пикселя сравнение готовой альфы с сохранённым MRQ RGB `.substrate-rgb.bak` по LUT; для FH — отдельная формула fallback levels + reference curve. Проверяется также чёрный RGB.
- Нулевая ошибка native audit доказывает правильность применения преобразования, но сама по себе не доказывает совпадение света с историей.
- Проверка `noVerticalClipping` относится только к верхней/нижней границе оптимизированного кропа. Это не обещание запаса со всех сторон: Fabric достигает боковых границ, а тень Bella — правой границы расширенного кадра. У high Bella эти bounds точно такие же и в старом референсе. Исходное горизонтальное кадрирование ради теста не менялось.

Референсы: `batch_7_20260828020546823` для Bella; `batch_16_20260901010513345` для Sand-секционки; калибровочные тени секционки — из `batch_16_20260831184843204`.

## Предупреждения и интерфейс

Unreal сообщает о почти нулевых tangents/binormals у двух UPH-мешей секционки. Это предупреждение исходной геометрии, не ошибка назначения материалов; грубых артефактов на просмотренных low-кадрах не обнаружено. Сообщение про отсутствующий frame-number token относится к именованию одиночных кадров; варианты имеют разные имена. `Failed fetch job: 204` после выполнения означает отсутствие следующей работы, не падение рендера.

С помощью computer-use/браузера проверены загрузка результатов, переключение Sand/White, desktop 1440×1000 и mobile 390×844. Горизонтального переполнения и ошибок browser console не обнаружено; все показанные изображения загрузились. Это проверка текущего сценария, не исчерпывающий аудит каждого UI-контрола.

## Вывод

Локальная цепочка job → импорт/назначение материалов → калибровка или полный кадр → Fabric/Shadow → native alpha → POST работает в перечисленных сценариях. Обнаруженный отказ POST длинного пути устранён и проверен повторным POST и новым высоким прогоном секционки; ложный общий success при ошибке POST исправлен отдельным тестом. Плагин, свет, сцены и добавленные пользователем материалы во время исправления не менялись.

Нельзя утверждать, что весь результат полностью повторяет старые батчи: **Fabric секционки заметно светлее**, вероятнее всего вследствие сохранённых изменений карт освещения. Для Bella F высокого разрешения Fabric совпал точно, высокие тени обеих моделей близки к референсам. Разные высоты кадра дают небольшие попиксельные отличия даже при корректном восстановлении симметричного кропа. Если нужна побитовая эталонность, фиксировать нужно не только job, но и версии карт/материалов, режим кадра и разрешение.

Проверка не покрывает все модели каталога, все материалы, левые/U-секционки, камеры P/TQB и многоматериальный high batch целиком. Результат — подтверждение перечисленных сценариев, не гарантия отсутствия любых ошибок на произвольных данных. После завершения тестов локальная служба актуальна (`stale=false`), активного Unreal-процесса рендера нет.
