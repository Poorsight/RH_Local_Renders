## Как работает цепочка

1. Тулза формирует job и запускает Unreal через свой штатный серверный маршрут `/api/renders`. Отдельный Python-адаптер переписанного плагина здесь не используется.
2. При отсутствии подходящего локального кропа выполняется калибровочная пара Fabric + Shadow. Кроп и формирование финальных размеров остаются в тулзе.
3. Fabric рассчитывает камеру; фактическое состояние передаётся фазе Shadow.
4. Обе фазы работают с Substrate ON. После записи MRQ PNG плагин внутри процесса Unreal преобразует RGB тени в чёрное RGBA по калибровочной LUT.
5. Исходный RGB сохраняется рядом как `.substrate-rgb.bak`. Готовность кадра сообщается после обработки. При ошибке обработки этот путь не отправляет событие успешного кадра.
6. Тулза создаёт preview и delivery POST, но повторно не извлекает альфу из RGB. `recoverLegacyShadow=false`, `nativeShadowAlpha=true`.

Это C++-обработка файла после MRQ внутри Unreal, а не новый GPU-проход и не внешняя обработка сервером. Материал Composure в текущем проекте сохранён без изменений.

Preflight проверяет наличие исходника, LUT и маркера обработчика в собранной DLL. Это статическая проверка возможностей, не гарантия успешного произвольного рендера. Ключ кэша камеры/кропа теперь также учитывает editor DLL, LUT и `M_shadow_only`, чтобы не подмешивать результаты прежнего теневого конвейера.

## Ограничения и воспроизведение

Исторические `BELGIAN_LINEN_CLASSIC_SAND_V1` и `UPH_WOOD_BROWN_OAK` отсутствуют среди доступных материалов текущего проекта. Поэтому это техническая проверка механизма, а не доказательство совпадения старого света или материала Bella. Для такого сравнения нужно вернуть соответствующие assets и повторить одинаковые настройки/разрешение.

Проверка нативной альфы без изменения изображений:

```powershell
node scripts/audit-native-shadow.cjs "<полный путь к raw Shadow.png>" "D:/GitHub/rh_unreal_2/Plugins/BatchRender/Config/ShadowAlphaLut.json"
```

Этот аудит проверяет применение LUT к сохранённому входному RGB, а не физическую правильность света и не визуальную эквивалентность другой сцене. Для камер без прямой LUT утилита намеренно требует отдельной проверки fallback.

Переключать ветки следует только при остановленной очереди/рендере, затем перезапускать локальную службу. Игнорируемые папки jobs/renders/cache общие для веток в одном checkout; новые тесты имеют отдельные идентификаторы и не заменяют старые результаты.
